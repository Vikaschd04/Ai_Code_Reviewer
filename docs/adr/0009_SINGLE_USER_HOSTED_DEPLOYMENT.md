# ADR 0009 — Single-user hosted deployment on Render (amended: UI served by the container)

Status: accepted and implemented, 27 September 2026 (user request after P02); **amended the same day**: at the user's request the complete application runs on Render — the container serves the built web UI on the API's own origin and the Vercel configuration was removed. The original split-hosting decision is kept below for history. Owner: development agent for the repository maintainer.

Amendment 2 (29 September 2026, free trial): the owner wants to test without paying. No always-on free host fits (Render free: no disk, sleeps, 30-day DB; Railway: one-time $5 trial with 1 GB RAM/1 GB disk, then 0.5 GB RAM; Hugging Face Docker Spaces now need a paid plan). GitHub Codespaces runs the same image for free within the personal monthly quota (usage stops, is not charged, without a payment method): `.devcontainer` (Ubuntu + docker-in-docker) starts `deploy/codespace.sh`, which generates secrets under `.local/codespace/`, derives the public host from `CODESPACE_NAME`/`GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN`, and runs `deploy/docker-compose.yml` (PostgreSQL 18 + app; also allows `localhost`/`127.0.0.1` hosts for the port forwarder). CI starts the app through the same script with a simulated codespace. The Render Blueprint remains for a paid always-on URL.

Amendment (Render only): a `web` build stage compiles `apps/web` into `/app/web-dist`; the API mounts it at `/` (`CRP_WEB_STATIC_DIR`, routes under `/v1` take precedence, strict CSP for HTML, immutable caching for hashed assets). In hosted mode the allowed web origin defaults to the service's own `https://` address derived from `RENDER_EXTERNAL_HOSTNAME`, so the Blueprint needs no input (database URL wired, access token generated). Upload tickets remain (same-origin now; still allow a separately hosted UI via `CRP_ALLOWED_WEB_ORIGINS`). The Dockerfile no longer uses BuildKit heredocs (`deploy/fetch_temporal.py` downloads and verifies the Temporal CLI). Evidence: `test_container_serves_the_web_ui_on_the_api_origin`, `test_same_origin_defaults_when_the_container_serves_the_ui`, the hosted smoke tests (UI served by the real entrypoint) and the CI container smoke test (checks `/` and its CSP).

Context: the user asked for a public URL with continuous deployment from GitHub (`Vikaschd04/Ai_Code_Reviewer`) and chose "Vercel UI + container host" after being told Vercel cannot host the backend. Until now the API refused non-loopback clients (ADR 0004) and hosted exposure was planned for P07. The analyzers need Java/Node runtimes, ~800 MB of binaries, a 1.3 GB offline DB and a long-running worker; Vercel Functions cap bodies at 4.5 MB and proxied requests at 120 s.

Decision:

- **Split hosting.** Vercel builds and serves the static UI from the repository root (`vercel.json`, exact pnpm via `npx pnpm@11.20.0`) and rewrites `/v1/*` to the Render backend, keeping the API same-origin so the HttpOnly SameSite=Strict session cookie design is unchanged. Render runs one Docker web service from `render.yaml` (Blueprint) with a 10 GB disk and a private PostgreSQL 18 database, deploying `main` only after CI passes.
- **`CRP_ENVIRONMENT=hosted`** (new tier, single user): public bind allowed only with an explicit Host allowlist (`CRP_PUBLIC_HOSTS`), https-only web origins (+ optional anchored preview-origin regex), an https `CRP_PUBLIC_API_URL`, Secure cookies, HSTS, and an access token of ≥ 32 characters. Local/test tiers keep the loopback guard unchanged. Platform `postgres://` URLs are normalized.
- **Direct uploads with tickets.** `POST /v1/intakes/{id}/upload-ticket` issues a 15-minute HMAC ticket (key derived from the access token) valid for one intake; the browser PUTs the ZIP to the API host with the ticket and no credentials; CORS allows only PUT from configured web origins without credentials. The same path is used locally (relative URL), so there is one upload implementation.
- **One container, one process tree.** `crp-dev hosted` starts the Temporal dev server with SQLite on `/data`, migrates, keeps the Trivy DB fresh daily in the background (the only network use; scans stay offline), and supervises API + worker; any exit stops the container so the platform restarts it. The entrypoint fixes disk ownership as root and then permanently drops to uid 10001 (`setpriv`).
- **Supply chain.** Base images pinned by digest (python 3.14-slim-trixie, node 22-trixie-slim, uv 0.12.19); Linux x86_64 Opengrep/Trivy pinned by SHA-256 after checking project checksums, GitHub asset digests and cosign signatures; Temporal CLI pinned by SHA-256 from its checksums file; GitHub Actions pinned to commit SHAs. The ESLint runner ships as a self-contained `pnpm deploy` of the frozen lockfile; `typescript` became a runtime dependency (typescript-eslint needs it to parse TS).
- **Verification loop without local Docker** (disk too small for a VM): the hosted entrypoint is tested end-to-end on macOS (`test_hosted_smoke.py`), and CI builds the Linux image and runs `deploy/smoke_test.py` against it with a real PostgreSQL service.

Alternatives considered: frontend-only on Vercel (URL without a working app); Vercel Functions for the API (body/time limits, no worker); Temporal Cloud + managed Postgres + separate worker service (more cost and moving parts for one user; revisit in P07); proxying uploads through Vercel (undocumented body limit for external rewrites; tickets avoid the dependency); bearer tokens in browser storage for cross-origin API calls (weaker than HttpOnly cookies).

Consequences: the deployment is single-user and single-instance; it is not the P07 multi-tenant/SSO design. There is still no per-scan OS sandbox (container isolation only). Upload tickets are bearer credentials for 15 minutes for one intake. SSE is subject to Vercel's 120 s proxy timeout (reconnect + polling). Paid Render resources are required; the owner confirms prices in Render.

Evidence: `packages/core/tests/test_config.py` (hosted validation), `services/api/tests/test_hosted_mode.py` (Host allowlist, CORS, Secure cookies, tickets), `tools/devtools/tests/test_hosted_env.py`, `tools/devtools/tests/test_hosted_smoke.py` (real entrypoint, all engines, CI smoke script), `.github/workflows/ci.yml` container job; docs/DEPLOYMENT.md.
