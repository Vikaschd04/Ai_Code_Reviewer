# Deployment: Vercel (web UI) + Render (backend)

Status: configuration implemented and tested locally (hosted entrypoint end-to-end) and in CI (Linux image build + smoke test). The live deployment requires the account steps below, which only the repository owner can perform.

## What runs where

```
browser ──https──► Vercel (static React UI, auto-deploys every push)
                     │  /v1/*  rewrite (same-origin API, HttpOnly session cookie)
                     ▼
                   Render web service "ai-code-reviewer-api" (Docker, 1 CPU / 2 GB, Singapore)
                     ├─ crp-dev hosted: API (uvicorn) + Temporal worker + Temporal dev server
                     ├─ PMD 7.27.0 (Java 21 JRE), ESLint 10.11.0 (Node 22), Opengrep 1.30.0, Trivy 0.69.3
                     ├─ /data persistent disk (10 GB): artifacts, scan work area, Temporal SQLite,
                     │   offline Trivy DB (downloaded at first boot, refreshed daily)
                     └─ PostgreSQL 18 "ai-code-reviewer-db" (private: no external connections)
browser ──https──► Render API host directly, only for ZIP uploads (15-minute upload ticket)
```

Why not everything on Vercel: the worker is a long-running process, the analyzers need ~800 MB of binaries plus a 1.3 GB vulnerability database and Java/Node runtimes, and Vercel Functions cap request bodies at 4.5 MB and proxied requests at 120 s. Vercel serves the UI and proxies API calls; uploads go straight to the backend with a signed ticket so they do not depend on proxy limits.

## One-time setup (repository owner)

1. **Vercel (UI)** — vercel.com → *Add New… → Project* → import `Vikaschd04/Ai_Code_Reviewer`. Keep the root directory as the repository root; `vercel.json` supplies the install/build commands and output directory. Name the project `ai-code-reviewer` so the production URL is `https://ai-code-reviewer.vercel.app` (Vercel shows the actual URL after the first deploy). Every push to `main` deploys production; other branches/PRs get preview URLs.
2. **Render (backend)** — render.com → *New → Blueprint* → connect the GitHub repository → Render reads `render.yaml` and proposes the web service, disk and database. When prompted:
   - `CRP_ALLOWED_WEB_ORIGINS` = the Vercel production URL from step 1, e.g. `https://ai-code-reviewer.vercel.app` (comma-separate several).
   - `CRP_ALLOWED_WEB_ORIGIN_REGEX` = optional, to allow Vercel preview URLs, e.g. `^https://ai-code-reviewer-[a-z0-9-]+\.vercel\.app$`. Leave empty to allow production only.
   - `CRP_ACCESS_TOKEN` is generated by Render. The Blueprint uses paid plans (web `1c-2g`, disk 10 GB, database `0.1c-256mb`); Render shows the monthly price before you confirm.
3. **Backend URL** — after the first Render deploy, check the service URL. If it is not `https://ai-code-reviewer-api.onrender.com`, update the two occurrences in `vercel.json` (rewrite destination and `connect-src`) and push.
4. **Sign in** — open the Vercel URL and sign in with the value of `CRP_ACCESS_TOKEN` (Render dashboard → service → *Environment*). The first boot downloads the Trivy database; until it finishes, scans report Trivy as UNAVAILABLE (honest state), and the other engines work.

## Continuous deployment

- Push to `main` → GitHub Actions `ci` (lint, types, contracts, unit tests, web build, Linux image build and container smoke test) → Render deploys only if checks pass (`autoDeployTrigger: checksPass`); Vercel builds the UI.
- Database migrations run automatically at container start (Alembic, idempotent).
- Rotate the sign-in token: change `CRP_ACCESS_TOKEN` in Render and redeploy; all sessions and upload tickets are invalidated.

## Security posture (read before sharing the URL)

This is a **single-user** hosted mode (`CRP_ENVIRONMENT=hosted`), not the multi-tenant/SSO deployment planned for P07:

- One shared access token (≥ 32 characters) signs in; failed sign-ins are throttled. Sessions are HttpOnly, Secure, SameSite=Strict cookies on the Vercel domain.
- The API answers only its configured Host names (liveness excepted), requires allowed Origins for cookie-authenticated changes, sends HSTS, and allows CORS only for ticket uploads from the configured web origins (no credentials).
- Uploaded source is stored on the Render disk and database. Upload only code you are allowed to store with that provider.
- Analyzers run as an unprivileged user inside the container with bounded time/output/heap, on copies of the snapshot; they do not execute uploaded code. There is still no per-scan OS sandbox (KNOWN_ISSUES K-P01-01), which is why this mode is single-user.
- No source is sent to any AI provider.

## Running the hosted mode yourself

`crp-dev hosted` is the container entrypoint and also runs on a workstation (used by `tools/devtools/tests/test_hosted_smoke.py`). Required environment: `CRP_ACCESS_TOKEN`, `CRP_DATABASE_URL` or `DATABASE_URL`, `CRP_ALLOWED_WEB_ORIGINS`, `CRP_PUBLIC_HOST` (or Render's `RENDER_EXTERNAL_HOSTNAME`); optional `PORT`, `CRP_DATA_DIR`, `CRP_ALLOWED_WEB_ORIGIN_REGEX`, `CRP_EXTRA_PUBLIC_HOSTS`, `CRP_TEMPORAL_PORT`, `CRP_TRIVY_DB_AUTO_REFRESH=0`, and `CRP_INTAKE_*`/`CRP_ENGINE_*` overrides. Other container hosts (Railway, Fly.io, a VM) work with the same image, a persistent volume at `/data` and those variables.

## Known limits

- Engine binaries are pinned for Linux x86_64 and macOS arm64 only (Render and GitHub runners are x86_64).
- Temporal runs as the single-node dev server with SQLite on the disk: suitable for one instance, not for horizontal scaling (P07: managed Temporal).
- Live-progress events (SSE) pass through Vercel's 120 s proxy limit; the UI reconnects and also polls.
- The Render service scales to one instance (the disk is attached to one instance).
