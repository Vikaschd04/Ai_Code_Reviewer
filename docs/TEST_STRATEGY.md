# Test strategy

Tests establish behavior at concrete risks. Keep fixtures synthetic, small and named by purpose; do not commit customer source, real secrets or licensed SDKs.

| Layer | Required focus |
|---|---|
| Unit | State transitions, canonical paths/hashes, normalization, budgets |
| Property/fuzz where justified | Archive/path boundary invariants and malformed parser inputs |
| Adapter contract | Real representative output, exit semantics, coverage, crash/timeout/cancel |
| Integration | DB migrations, artifact lifecycle, workflow retries, tenant predicates |
| Browser E2E | Upload, scope/progress, evidence navigation, errors, cancellation, patch review |
| Domain fixtures | Positive/negative SAP/Salesforce rules and metadata relationships |
| Adversarial AI | Untrusted instructions, missing anchors, secret leakage, unauthorized retrieval |
| Benchmarks | Dataset/hardware/tool versions, throughput, memory, cost and partial failure |

Phase 1 must execute real PMD/ESLint scans of seeded and clean examples. Test doubles are acceptable for deterministic failure/provider simulation, but never presented as engine integration proof.

Phase 3 evaluations use adjudicated positive/negative cases and held-out examples. Report precision and labelled-case recall by domain with sample sizes; no global production recall claim. Record source-anchor validity and cost per accepted finding. Human suggestion acceptance is useful feedback, not correctness proof.

Phase 5 repairs must preserve existing checks; added regression tests should fail on the original defect and pass after a correct fix when meaningful. Generated tests cannot redefine business behavior. Mark unavailable platform/build checks explicitly.

For each phase create docs/validation/Pxx_REPORT.md from the template: environment, exact commands, exit/outcomes, artifacts, mandatory gates and gaps. A failed/blocked mandatory gate prevents COMPLETE. UI work includes browser inspection where runnable. Broaden testing when a specific risk or gate requires it; avoid repetitive unrelated full-suite runs.

Proposed scale qualification tiers are 100k and 1M eligible LOC plus a smaller PR workload. Determine SLOs after measurements on specified hardware; this kit has no measured capacity. Include resource exhaustion, tenant fairness, parser failure and restart tests, not only happy-path timing.


## Implemented suites (P00)

| Suite | Location | Real dependencies |
|---|---|---|
| Core unit | `packages/core/tests` (config, artifact containment, states, secrets, redaction) | filesystem |
| Migrations/integrity | `packages/core/tests/test_migrations.py` | ephemeral PostgreSQL 18 |
| API | `services/api/tests` (health/auth/sessions/loopback, projects scoping/pagination, contract drift) | ephemeral PostgreSQL 18; Temporal outage simulated by a labelled test double |
| Durable workflow smoke | `services/worker/tests/test_workflow_smoke.py` | ephemeral PostgreSQL + Temporal dev server + in-process worker via the real API |
| Dev tooling | `tools/devtools/tests` (context exclusion/truncation/cache/no-execution) | filesystem |
| Runner | `tools/local-runner/tests` | HTTP test double (unit scope) |
| Web unit | `apps/web/src/**/*.test.ts(x)` (vitest + jsdom; synthetic display fixtures) | none |
| Browser E2E | `apps/web/e2e` via `make test-e2e` | isolated PostgreSQL, Temporal, API, worker, production web build, Chrome |

Integration tests are marked `integration`; missing PostgreSQL/Temporal binaries make them error, not skip. `make test SCOPE=unit` runs only non-integration tests.
